§ 1.1 · the four reasons

왜 이런 환경이 필요할까요

  1. 제안서는 시간이 곧 비용입니다.
    처음부터 슬라이드를 디자인하는 시간은 본문을 쓰는 시간보다 훨씬 더 깁니다.
  2. 글로 빨리 쓰는 사람들이 많습니다.
    하지만 회사에 낼 최종 결과물은 파워포인트(PPT)나 PDF여야 할 때가 많죠. 글과 PPT 사이의 다리가 필요합니다.
  3. 회사 양식은 그대로 써야 합니다.
    자유롭게 디자인하는 게 아니라, 회사가 정해 둔 슬라이드 모양에 내용만 채워야 하는 경우가 많습니다.
  4. AI에게 시켜도 톤이 자꾸 흔들립니다.
    한 슬라이드는 좋은데 다른 슬라이드는 너무 다른 분위기… 일관성을 유지할 규칙이 필요합니다.

§ 3.1 · issue no. 01

설치가 갑자기 실패할 때

증상

"적용 가능한 설치 관리자를 찾을 수 없습니다"

§ 3.3 · issue no. 03

"명령을 쳤는데 클로드가 못 알아들어요"

증상

/plugin install 만 실행되고 인자가 빠짐

붙여넣기 할 때 명령과 그 뒤의 단어 사이에 줄바꿈이 끼면, 클로드 코드는 첫 줄만 명령으로 받습니다. 두 번째 줄은 그냥 일반 메시지로 처리되어 "직접 입력해 주세요"라는 답을 받게 됩니다.

해결

반드시 한 줄로 입력

입력창을 비우고 /plugin install document-skills@anthropic-agent-skills 를 줄바꿈 없이 한 줄로. 붙여넣은 뒤 보이는 모든 개행은 백스페이스로 합치고 엔터. 슬래시 명령은 멀티라인을 지원하지 않습니다.

§ 3.4 · issue no. 04

공식 스킬을 손으로 복사하면 안 됨

증상

git clone으로 직접 복사하면 라이선스 위반

정식 경로 — /plugin install 만 사용

클로드 코드 안에서 /plugin marketplace add 와 /plugin install 두 줄로 설치하면 "서비스 안에서의 사용"으로 인정됩니다. 코드를 받기 전엔 LICENSE 파일부터 읽는 습관을.

자바스크립트로 쓴 코드를 컴퓨터에서 돌리는 엔진. 일종의 통역사.
Python 파이썬
컴퓨터 일을 자동화하는 데 많이 쓰는 프로그래밍 언어. 초보자가 배우기 쉬움.

Playwright 플레이라이트

AI 디자인이 들키는 7가지 클리셰

"무엇을 하지 말 것"이 "무엇을 할 것"보다 더 많은 분량으로 명문화될 때, 디자인은 평범함을 벗어납니다. — Claude Design 시스템 프롬프트 분석에서

  1. 보라·핑크 그라데이션 배경. "활기차 보이려는" AI 디자인의 단골 — 시그니처 색이 아닌 이상 금지.
  2. 카드 + 그림자 + rounded-2xl 콤보. Tailwind 기본형의 함정. 모든 화면이 같은 톤으로 수렴된다.
  3. 둥근 모서리 + 좌측 액센트 보더. Claude Design이 가장 명시적으로 금지하는 컨테이너 패턴. 한눈에 AI로 인식됨.
  4. Inter / Roboto / Arial 단독 사용. 과사용된 산세리프 — 식별 가능한 페어(세리프 디스플레이 + 산세리프 본문)로 대체.
  5. SVG로 그린 가짜 일러스트. 잘 그릴 자신이 없으면 차라리 플레이스홀더가 낫다.
  6. 데이터 슬롭. 의미 없는 숫자·통계·아이콘으로 빈 공간 채우기 — 모든 요소는 자기 자리를 벌어야 한다.
  7. 장식용 이모지. 브랜드가 쓰지 않으면 노이즈. 텍스트와 마지널리아만으로 충분하다.
